# 语法总结

## LlamaIndex的RAG

`LlamaIndex`（原名 GPT Index）是一个数据开发框架，核心使命是**打通私有数据与通用大模型之间的壁垒** 

文档核心给出了基于 LlamaIndex 的完整代码实现链路，以下是必须掌握的关键组件：

### **文档加载（读取数据）**

**注意事项**：为什么用DocxReader读取word，word有很多页只读出一个文档，但是PDFReader读取pdf，每一页都是一个文档

​	**直接原因**：这完全是 **PDF 和 Word 两种文件==底层逻辑==的根本差异** 导致的，而不是 LlamaIndex 故意厚此薄彼。

==**文档.doc**==

- **底层存储**：`.docx` 文件本质上是一个 **Zip压缩包**，里面包含了一个 `document.xml` 文件。这个XML文件是一个**连续的、流式的文本流**。
- **没有“分页”概念**：Word里的“分页”是**动态渲染**出来的。同样的内容，你用A4纸打印是一种分页，用A3纸打印是另一种分页，在手机上看又是另一种分页。
- **解析器行为**：`DocxReader` 调用底层的 `python-docx` 或 `docx2txt` 库时，只能按照XML的节点顺序把文字全部抠出来拼成一个完整的长字符串。它无法在物理层面确定“第1页在哪里结束、第2页在哪里开始”，所以只能合并为 **1个文档**。

==**文档.pdf**==

- **底层存储**：PDF 不是文本文件，它是一个**画布指令集**（坐标集合）。它不关心“段落”，只关心“在第(x,y)坐标处放置字母A，在(x2,y2)处放置字母B”。
- **天然物理边界**：PDF 有绝对的“页”概念（Page）。每一页都是一个独立的画布对象（Object），页与页之间在底层数据里是完全隔开的。
- **解析器行为**：`PyMuPDFReader` 在解析时，会遍历每一页（Page Object），把该页画布上的文字提取出来，生成一个独立的 `Document` 对象。所以 **10页PDF = 10个Document对象**。

#### **代码解析**:

`enumerate` 是 Python 内置的一个**“计数器”函数**。它的核心作用可以用一句话概括：

> **在遍历一个列表（或其他可迭代对象）时，同时拿到“当前是第几个”和“当前元素是什么”。**

- 它返回的是一个**惰性迭代器**（Lazy Iterator），每循环一次，它就吐出一个**元组 (tuple)**。
- 这个元组固定包含两个值：**(索引, 元素)**。

代码 `for i, doc in enumerate(documents):` 中，它帮你把**循环次数**（索引）和**文档对象**同时解包出来。



代码 `print(f"第一个文档元数据: {documents[0].metadata}")` 中，`documents` 的内部结构是一个**Python 列表（List）**，列表里的每个元素都是一个**`Document` 对象**。

### **文档分块（Chunking）—— RAG 效果的关键**

文档详细对比了三种切分器，这是必须掌握的实践技能：

| 切分器                         | 核心逻辑                   | 特点                                                         |
| :----------------------------- | :------------------------- | :----------------------------------------------------------- |
| **TokenTextSplitter**          | 按 Token 数量硬切          | 严格控制LLM上下文窗口，但会割裂句子                          |
| **SentenceSplitter**           | 按句子边界切分             | **常规RAG推荐**，兼顾句子完整性与长度控制                    |
| **SemanticSplitterNodeParser** | 基于句子语义相似度动态切分 | 语义连贯性好，但计算开销大，且**文档特别提醒：主要适用于英文，需调优阈值** |

#### `TokenTextSplitter`  vs  `SentenceSplitter`

**分块重叠**：建议 `chunk_overlap` 为 `chunk_size` 的 **10-20%**（用于保持上下文连贯）

#### `SemanticSplitterNodeParser`

**语义切分参数**：`buffer_size=1`（组合句含3个句子），`breakpoint_percentile_threshold=95`（越高切分越粗）

执行顺序：

1. 先按句子切分（默认按句号、换行等）
2. 把相邻句子组合成"组合句"（combined sentences）
3. 对每个组合句调用 Embedding 模型计算相似度
4. 根据相似度阈值决定切分点。

```python
import os
from llama_index.core import Document, SimpleDirectoryReader
from llama_index.core.node_parser import SemanticSplitterNodeParser

# 千问嵌入模型
from llama_index.embeddings.dashscope import DashScopeEmbedding

# ===================== 关键修复：过滤空文本 =====================
def clean_empty_text(documents):
    """
    过滤掉文档列表中的空文本或纯空白字符文档。
    Args:
        documents (list): 原始文档列表  
    Returns:
        list: 清洗后的文档列表，仅包含非空文本
    """
    clean_docs = []
    for doc in documents:
        # 去掉首尾空白、换行符，只保留有效文本内容
        text = doc.text.strip()
        if text:  # 只保留非空文本，避免后续处理报错
            clean_docs.append(Document(text=text, metadata=doc.metadata))
    return clean_docs

# ===================== 千问配置 =====================
# 初始化 DashScope 嵌入模型，用于语义相似度计算
embed_model = DashScopeEmbedding(
    model_name="text-embedding-v3",  # 使用通义千问 v3 嵌入模型
    api_key=os.getenv("DASHSCOPE_API_KEY"),  # 从环境变量获取 API Key
    text_length=2048  # 最大文本长度限制
)

# ===================== 语义切分器配置 =====================
# 创建语义切分器，根据语义相似度动态分割文档
splitter = SemanticSplitterNodeParser(
    buffer_size=1,   # 缓冲区大小，影响上下文连贯性
    breakpoint_percentile_threshold=95,  # 断点阈值，越高分割越粗粒度
    embed_model=embed_model  # 指定使用的嵌入模型
)

# ===================== 读取文件 + 清理空文本 =====================
# 初始化文档阅读器，指定要加载的文件路径
reader = SimpleDirectoryReader(
    input_files=[
        "./data/sample.pdf",
        "./data/citys.csv",
        "./data/kq.txt"
    ]
)
# 加载原始文档数据
documents = reader.load_data()       

# ✅ 关键步骤：过滤空文本（防止因空文档导致嵌入或切分报错）
documents = clean_empty_text(documents)

# ===================== 执行语义切分 =====================
# 使用语义切分器将文档拆分为节点
nodes = splitter.get_nodes_from_documents(documents)

# ===================== 输出结果 =====================
print("切分完成！节点数量：", len(nodes))
# 打印前5个节点的预览信息
for i, node in enumerate(nodes[:5]):
    print(f"Chunk {i}: {len(node.text)} 字符")
    print(node.text)
    print("=" * 50)
```

### **向量化与存储（Embedding + Vector DB）**

- **向量化**：文档使用 **DashScopeEmbedding**（通义千问 `text-embedding-v3`），并强调注意 **8192 tokens 长度限制**和 **batch size=10** 的限制。
- **存储**：使用 **ChromaDB** 持久化（`chromadb.PersistentClient`），通过 `ChromaVectorStore` 适配器将 LlamaIndex 的 Node 写入 Chroma Collection。
- **核心机制**：`VectorStoreIndex(nodes, storage_context)` 会自动遍历节点调用 Embedding 模型并写入数据库。

==关键执行顺序：==

![image-20260701191953509](./LlamaIndex 语法.assets/image-20260701191953509.png)

```python
# 标准库：用于读取环境变量（如 API Key）
import os

# LlamaIndex 核心模块
from llama_index.core import (
    SimpleDirectoryReader,  # 文档加载器：从目录或文件列表读取文档
    VectorStoreIndex,       # 向量索引：用于存储和检索向量嵌入
    StorageContext,         # 存储上下文：管理向量存储、文档存储等
    Settings,               # 全局设置：配置嵌入模型、LLM 等
)

# 节点解析器：将文档切分为更小的文本块（按句子边界智能切分）
from llama_index.core.node_parser import SentenceSplitter

# 通义千问嵌入模型：用于将文本转换为向量表示
from llama_index.embeddings.dashscope import DashScopeEmbedding

# Chroma 向量存储适配器：LlamaIndex 与 Chroma 的集成接口
from llama_index.vector_stores.chroma import ChromaVectorStore

# ChromaDB 客户端：用于创建和管理 Chroma 向量数据库
import chromadb


# ========== 配置 ==========
# 设置千问 Embedding API Key
# os.environ["DASHSCOPE_API_KEY"] = "你的-dashscope-api-key"

# 全局设置：使用千问 text-embedding-v3
Settings.embed_model = DashScopeEmbedding(
    model_name="text-embedding-v3",  # 千问 embedding v3
    text_type="document",             # document 或 query
)

# ========== 1. 加载文档 ==========
documents = SimpleDirectoryReader(
    input_files=["目录路径"],
    recursive=True,
    required_exts=[".pdf", ".txt", ".md", ".csv"],
).load_data()

# ========== 2. 文档切分 ==========
splitter = SentenceSplitter(
    chunk_size=512,      # 每个 chunk 约 512 tokens
    chunk_overlap=128,   # 重叠 128 tokens，保证上下文连贯
    paragraph_separator="\n\n\n",  # 段落分隔符
    secondary_chunking_regex="[^,.;。]+[,.;。]?"  # 辅助切分正则
)
nodes = splitter.get_nodes_from_documents(documents)

# ========== 3. 向量化并存储到 ChromaDB ==========
# 创建 Chroma 客户端
chroma_client = chromadb.PersistentClient(path="./chroma_db")  # 

# 创建或获取 collection
collection = chroma_client.get_or_create_collection(name="集合名")

# 创建向量存储对象
#  1、创建一个适配器对象，让 LlamaIndex 能"看懂"这个 Chroma collection
#  2、完成 存储适配。提供 add(), delete(), query() 等方法
#  3、在 LlamaIndex 的 Node 对象 和 ChromaDB 的存储格式之间做双向转换
vector_store = ChromaVectorStore(chroma_collection=collection)

# 创建存储上下文
# 1、它是 LlamaIndex 的"存储上下文组装器"，负责整合所有存储组件
# 2、在 LlamaIndex 的架构中，索引（Index）不直接操作存储，而是通过 StorageContext 间接访问。这个函数的职责
storage_context = StorageContext.from_defaults(vector_store=vector_store)

# ======= 4. 构建索引（自动做向量化并存储）=====================
index = VectorStoreIndex(
    nodes=nodes,
    storage_context=storage_context,
)


print(f"✅ 加载了 {len(documents)} 个文档")
print(f"✅ 切分为 {len(nodes)} 个节点")
print("✅ 向量化和存储完成！")
print(f"✓ 获取或创建集合: {collection.name}")
print(f"文档数:{collection.count()}")
```

### **检索与问答（Query Engine）**

- 加载已存在的向量库：`VectorStoreIndex.from_vector_store(vector_store)`。

# - token_limit=10000：记忆最多保留 10000 tokens，超出会自动删除最早的对话
memory = ChatMemoryBuffer.from_defaults(token_limit=10000)

# 准备5：创建聊天引擎（RAG 问答核心组件）
# as_chat_engine() = 智能聊天机器人（有记忆、有角色、能对话）
# as_query_engine() = 智能搜索引擎（无记忆、单次查询、快准狠）
# 用户会不会连续问多个相关问题？   用 as_chat_engine 反之 as_query_engine
query_engine = index.as_chat_engine( 
    # chat_mode='condense_plus_context',  # 聊天模式：压缩问题+上下文（适合复杂多轮对话）
    memory=memory,  # 绑定聊天记忆，支持多轮对话上下文
    system_prompt='你是一个麦当劳助手，根据检索的内容，用简体中文回答问题',  # 系统提示词：定义 AI 的角色和行为规范
)

while True:
    question = input("\n❓ 请输入问题（q退出）: ")
    if question.lower() == 'q':
        break
    # 回答问题。
    response = query_engine.chat(question)   # 回答问题格式
    print(f"\n💡 回答:\n{response}")
