## 一、RAG 基础认知（必读）

### 1.1 什么是 RAG？

- **Retrieval-Augmented Generation**（检索增强生成）
- **本质**：给大模型（LLM）外挂一个可随时更新的知识库，先**检索**相关文档片段，再让LLM基于**这些片段**生成答案。
- **解决三大痛点**：
	1. **幻觉**：LLM编造不存在的事实 → 用检索到的真实内容约束生成。
	2. **知识滞后**：训练数据有截止日期 → 只需更新外部知识库，无需重训模型。
	3. **私有数据不可用**：内部文档无法上传云端 → 本地/内网部署RAG，数据不出域。

### 1.2 RAG 与纯 LLM 的区别（面试高频）

| 维度     | 纯 LLM                             | RAG                                     |
| :------- | :--------------------------------- | :-------------------------------------- |
| 知识来源 | 仅靠训练时记忆的参数化知识         | 参数化知识 + 随时更新的外部非参数化知识 |
| 时效性   | 固定于训练截止日期，更新需重新微调 | 更新知识库即可，实时生效                |
| 幻觉控制 | 对未知内容容易胡编                 | 有明确上下文依据，可强制“不知道就不答”  |
| 领域适配 | 需要大量微调数据和算力             | 只需准备领域文档，成本极低              |

### 1.3 RAG 核心流程（Naive RAG 基线）

1. **离线阶段**：原始文档 → 解析 → 清洗 → 分块（Chunking） → 向量化（Embedding） → 存入向量库。
2. **在线阶段**：用户问题（Query） → 向量化 → 检索最相似的 Top‑K 个片段 → 拼接 Prompt → LLM 生成答案。

> ⭐ **重难点**：**分块策略**和**检索质量**直接决定最终效果，后续优化都围绕这两点展开。

## 二、两大阶段（离线 + 在线）

### 2.1 离线预处理阶段

- **目的**：将原始文档转换成可被高效检索的向量或结构化知识，一次性完成，不占用实时问答时间。

- **核心工作流程**（基于 LlamaIndex）：

	1. **文档加载**（`SimpleDirectoryReader` + 专用加载器）

		- 支持 PDF（`PDFReader`、`PyMuPDFReader`、`UnstructuredReader`）、Word（`DocxReader`）、CSV（`PandasCSVReader`）、Markdown/HTML/ipynb（`MarkdownReader`、`HTMLTagReader`、`IPYNBReader`）等。

		- 注意：**PDF 按页分割为多个 `Document` 对象**，而 Word 整体视为一个 `Document`（因为 PDF 有物理页边界，Word 是流式布局）。

		- 代码示例：

			```python
			from llama_index.core import SimpleDirectoryReader
			from llama_index.readers.file import PyMuPDFReader
			
			pdf_parser = PyMuPDFReader()  # 与通用加载器 区别1 声明一个对象
			
			# 导入Document库  自己写：documents = [Document(text='str')]
			documents = SimpleDirectoryReader(
			    input_dir="/目录路径",   # 指定要读取的目录路径 也可指定文件  input_files=["../文件路径"],
			    recursive=True,        # 表示递归遍历子目录
			    required_exts=[".pdf", ".txt", ".md", ".csv"]  # 可选：按扩展名过滤
			    file_extractor={".pdf": pdf_parser}
			    # 区别2 新增 {扩展名:加载器对象}  告诉SimpleDirectoryReader：遇到 .pdf 文件时，用 PDFReader 来解析
			    # 
			).load_data()
			# documents 是 List[Document]，每页一个 Document
			'''
			documents = [
			    # 索引 0（第1页）
			    Document(
			        text="这是第一页的文字内容...",
			        metadata={"file_name": "报告.pdf", "page_label": "1"},
			        id_="abc123"
			    ),
			    # 索引 1（第2页）
			    Document(
			        text="这是第二页的文字内容...",
			        metadata={"file_name": "报告.pdf", "page_label": "2"},
			        id_="def456"
			    ),
			    # 索引 2（第3页）
			    Document(
			        text="这是第三页的文字内容...",
			        metadata={"file_name": "报告.pdf", "page_label": "3"},
			        id_="ghi789"
			    )
			]
			'''
			```

			

	2. **文档分块（Chunking）** —— 关键步骤

		- 切割模型对中文很不友好，可以自定义中文友好函数，定义切割器时直接调用。

			```python
			# 1. 定义中文分句函数
			def chinese_sentence_boundary(text: str) -> list:
			    """
			    按中文标点（。！？）及换行符切割文本。
			    如果句子为空或纯空格，自动过滤掉。
			    """
			    # 用正则按 。 ！ ？ 以及换行符切分
			    raw_sentences = re.split(r'[。！？\n]+', text)
			    # 去除首尾空格，并过滤掉空字符串
			    return [s.strip() for s in raw_sentences if s.strip()]
			```

		

		- **固定大小分块**（`TokenTextSplitter`）：按 Token 数量硬切，可能割裂句子。

		- **句子边界分块**（`SentenceSplitter`）：推荐常规 RAG 使用，兼顾句子完整性与长度控制。

			```python
			import re
			from llama_index.core.node_parser import SentenceSplitter
			
			# 1. 定义中文分句函数（可以不写，但是一个中文不等于1 token，chunk_size可能约束不到位）
			def chinese_sentence_boundary(text: str) -> list:
			
			# 2. 实例化切割器时，通过 sentence_splitter 参数传进去
			splitter = SentenceSplitter(
			    chunk_size=512,                     # 每块最大长度
			    chunk_overlap=50,                   # 块与块之间的重叠
			    sentence_splitter=chinese_sentence_boundary  # 🔑 关键！替换默认英文分句
			)
			
			# 3. 正常调用切割
			nodes = splitter.get_nodes_from_documents(documents)
			```

			

		- **语义分块**（`SemanticSplitterNodeParser`）：基于句子间语义相似度动态切分，连贯性好但计算开销大，适合长文档。

			- 参数 `breakpoint_percentile_threshold` 控制切分敏感度(95 较粗，80 较细)。
			- 参数 `buffer_size=1` 控制一组几个句子(句子越多，语义切割效果越好)
			- ⚠️ 需要先加载 Embedding 模型，且注意中文句子拆分需自定义 `sentence_splitter`。

		```python
		import re
		from llama_index.core.node_parser import SemanticSplitterNodeParser
		from llama_index.embeddings.dashscope import DashScopeEmbedding
		
		# 1. 修复中文分句缺陷（必须写这个函数！）
		def chinese_sentence_splitter(text: str) -> list:
		    
		# 2. 初始化嵌入模型（建议用 v3，维度大一些语义更准）
		embed_model = DashScopeEmbedding(
		    model_name="text-embedding-v3",
		    api_key=os.getenv("DASHSCOPE_API_KEY")
		)
		
		# 3. 初始化语义切分器（所有参数写在一起）
		splitter = SemanticSplitterNodeParser(
		    embed_model=embed_model,                    # 【必填】算相似度的模型
		    buffer_size=1,                              # 看前后各1句，共3句
		    breakpoint_percentile_threshold=95,         # 只切最明显的5%跳变
		    sentence_splitter=chinese_sentence_splitter # 【关键】修复中文分句
		)
		```

		

	3. **向量化（Embedding）**

		- 使用 DashScope（通义千问）的 `text-embedding-v3` 或 `text-embedding-v4`。
		- 必须设置 `embed_batch_size=10` 避免 API 限流。

		```python
		from llama_index.embeddings.dashscope import DashScopeEmbedding
		
		Settings.embed_model = DashScopeEmbedding(
		    model_name="text-embedding-v3",
		    api_key=os.getenv("DASHSCOPE_API_KEY"),
		    embed_batch_size=10  # 默认25，因为text-embedding-v3和text-embedding-v4 单次只能处理10条文本，使用默认值会报错
		    text_length=2048  # 单条文本喂给模型的最大长度（单位：Token） text-embedding-v3和text-embedding-v4底层规定
		    text_type="document"  # 默认是document，告诉程序这个模型在  建立索引  时使用，text_type="query"在  检索时  使用
		    # 在真正的生产流程中，框架会自动根据“当前是在入库还是在提问”来帮你切换 LlamaIndex 会在检索时自动帮你切换
		)
		```

		

	4. **向量入库**（ChromaDB 持久化）

		- 使用 `chromadb.PersistentClient` 保存到磁盘，避免重复向量化。
		- 通过 `ChromaVectorStore` 适配器将 LlamaIndex 的 `Node` 写入集合。
		- 构建索引：`VectorStoreIndex(nodes, storage_context)` 会自动完成向量化 + 入库。

		```python
		import chromadb
		from llama_index.vector_stores.chroma import ChromaVectorStore
		from llama_index.core import StorageContext, VectorStoreIndex
		
		chroma_client = chromadb.PersistentClient(path="./chroma_db")
		collection = chroma_client.get_or_create_collection("my_kb")
		vector_store = ChromaVectorStore(chroma_collection=collection)
		storage_context = StorageContext.from_defaults(vector_store=vector_store)
		index = VectorStoreIndex(nodes, storage_context=storage_context)
		```

		

- ⭐ **重难点**：

	- **chunk_size** 和 **chunk_overlap** 的调优：过小导致上下文断裂，过大检索粒度粗。常规取 512~1024 token，重叠 10%~20%。
	- **Embedding 模型选择**：中文用 DashScope 或 BGE，英文用 OpenAI 或 Cohere。

### 2.2 在线推理阶段

- **目的**：实时响应用户提问，完成“检索 → 增强 → 生成”全链路。
- **主要步骤**：
	1. 用户输入 Query → 可能进行**查询改写/扩展**（检索前优化）。
	2. **检索**：从向量库中召回 Top‑K 候选片段（可混合 BM25）。
	3. **检索后优化**：重排序、压缩、去重，精炼上下文。
	4. **组装 Prompt**，调用 LLM（如 Qwen‑plus）生成答案。
	5. 返回答案（可附带引用来源）。
- ⭐ **重难点**：**延迟**与**准确性**的平衡，需结合索引优化（如 FAISS IVF/HNSW）和缓存策略。

## 三、三大核心模块

### 3.1 检索模块（Retrieval）

- **职责**：从知识库中找出与问题最相关的文本片段。
- **包含技术**：
	- **查询理解**：改写、扩展、HyDE、子查询分解（详见第四层检索前优化）。
	- **多路检索**：向量检索 + BM25 混合检索，多数据源并行召回。
	- **向量索引优化**：FAISS 的 IVF/HNSW 参数调优（`nlist`, `nprobe`, `efSearch`）。
- ⭐ **重难点**：**召回率（Recall）** 是 RAG 的天花板，主要负责找全   不遗漏。若检索不到正确答案，生成再好也无用。**准确率（Precision）**是从召回文本中挑选和问题相关的文本，保证相关性，剔除无用答案。

### 3.2 增强模块（Augment）

- **职责**：将检索到的原始碎片（可能含噪声、冗余）加工成高质量的 LLM 上下文。
- **包含技术**：
	- **重排序（Rerank）**：使用 Cross‑Encoder 模型（如 `DashScopeRerank`）对候选片段精细打分，截断 Top‑N。
	- **上下文压缩**：用 `SentenceEmbeddingOptimizer` 剔除无关句子，保留最相关部分。
	- **去重与过滤**：消除重复或低分片段。
	- **引用溯源**：在答案中标注信息来源。
- ⭐ **重难点**：**上下文窗口限制**（如 8K、128K），需在保留足够信息的同时压缩冗余。

### 3.3 生成模块（Generation）

- **职责**：基于问题 + 增强后的上下文，由 LLM 生成准确、可靠、无幻觉的答案。
- **包含技术**：
	- **Prompt 工程**：设计 System Prompt（角色、任务、约束、输出格式）。
	- **多轮对话记忆**：`ChatMemoryBuffer` 管理对话历史，实现上下文连贯。
	- **结构化输出**：要求 LLM 返回 JSON、表格等。
	- **幻觉抑制**：Self-RAG 的反思标记强制校验答案是否有证据支持。
- ⭐ **重难点**：**忠实度（Faithfulness）** —— 答案必须严格基于检索内容，不能编造。评估时可使用 `FaithfulnessEvaluator`。

## 四、四层架构 & 20 个优化点（核心知识体系）

> 此部分融合了 `Advanced RAG`、`Self-RAG & CRAG` 中的技术
>
> 按检索前→检索中→检索后→高级进阶 四层展开。

### 🔹 第一层：检索前优化（Pre-retrieval）—— 6 个优化点

**目标**：优化用户查询和文档索引，提高首次检索命中率。

#### ① 查询重写（Query Rewriting）

- **技术**：用 LLM 将口语化、模糊的问题改写为更清晰、更适合向量检索的表述。

- **实现**（继承 `BaseQueryTransform`）：

	```python
	from llama_index.core import PromptTemplate, QueryBundle
	from llama_index.core.indices.query.query_transform.base import BaseQueryTransform
	
	rewrite_template = PromptTemplate(
	    "请将用户查询改写得更加具体、详细，包含相关术语。只输出改写后的查询。\n"
	    "原始查询：{query_str}\n改写后："
	)
	
	class CustomRewriteTransform(BaseQueryTransform):
	    def __init__(self, llm, prompt):
	        super().__init__()
	        self._llm = llm
	        self._prompt = prompt
	
	    def _run(self, query_bundle, metadata):
	        rewritten = self._llm.complete(
	            self._prompt.format(query_str=query_bundle.query_str)
	        ).text.strip()
	        return QueryBundle(query_str=rewritten)
	```

	

- ⭐ **适用场景**：用户提问简短、不完整或带有错别字时效果明显。

#### ② 查询扩展（Multi-Query Expansion）

- **技术**：让 LLM 生成原问题的多个同义变体，并行检索后融合结果，扩大覆盖。

- **实现**：使用 `QueryFusionRetriever` 并设置 `num_queries>1`。

	```python
	from llama_index.core.retrievers import QueryFusionRetriever
	
	fusion_retriever = QueryFusionRetriever(
	    retrievers=[vector_retriever, bm25_retriever],
	    num_queries=3,                    # 1个原问题 + 2个变体
	    mode="reciprocal_rerank",         # RRF融合
	    llm=llm
	)
	```

	

- ⭐ **注意**：会增加 LLM 调用次数，适合对召回率要求高的场景。

#### ③ HyDE（假设文档嵌入）

- **技术**：先让 LLM 针对问题生成一个“假设性答案”，再用该答案的向量去检索，而非直接使用原始问题。因为假设答案与真实文档语义更接近。

- **实现**：`HyDEQueryTransform`

	python

	```python
	from llama_index.core.indices.query.query_transform import HyDEQueryTransform
	hyde = HyDEQueryTransform(llm=llm, include_original=True)  # 保留原问题
	query_engine = TransformQueryEngine(query_engine=base_engine, query_transform=hyde)
	```

	

- ⭐ **适合**：短查询、信息量不足的问题。

#### ④ 子查询分解（Sub-query Decomposition）

- **技术**：将复杂多条件问题拆成多个原子子问题，分别路由到不同知识库检索，最后汇总答案。

- **实现**：`SubQuestionQueryEngine`

	python

	```python
	from llama_index.core.query_engine import SubQuestionQueryEngine
	from llama_index.core.tools import QueryEngineTool, ToolMetadata
	
	tools = [
	    QueryEngineTool(
	        query_engine=policy_engine,
	        metadata=ToolMetadata(name="policy", description="政策法规信息")
	    ),
	    QueryEngineTool(
	        query_engine=finance_engine,
	        metadata=ToolMetadata(name="finance", description="财务数据")
	    )
	]
	sub_engine = SubQuestionQueryEngine.from_defaults(query_engine_tools=tools, llm=llm)
	response = sub_engine.query("政策对营收的影响及合规要求有哪些？")
	# 自动拆解为多个子问题，分别检索后综合
	```

	

#### ⑤ 文档分块优化（Chunking Optimization）

- **技术**：在离线阶段采用语义分块或层级分块，避免固定长度切断关键逻辑。

- **语义分块示例**（需 Embedding 模型）：

	python

	```
	from llama_index.core.node_parser import SemanticSplitterNodeParser
	splitter = SemanticSplitterNodeParser(
	    embed_model=embed_model,
	    breakpoint_percentile_threshold=95,   # 越高块越大
	    buffer_size=1                         # 窗口大小
	)
	nodes = splitter.get_nodes_from_documents(documents)
	```

	

- ⭐ **重难点**：`breakpoint_percentile_threshold` 和 `buffer_size` 需根据文档特点调优。

#### ⑥ 文档增强（Document Enrichment）

- **技术**：为每个分块附加摘要、关键词、反问句等元数据，丰富检索维度。

- **实践**：在构建 `Document` 时添加 `metadata`：

	python

	```
	doc = Document(
	    text="原始段落内容",
	    metadata={"summary": "这段讲的是考勤制度", "keywords": ["迟到", "旷工"]}
	)
	```

	

	检索时可利用元数据过滤（如 `where` 条件）。

### 🔹 第二层：检索中优化（Retrieval）—— 5 个优化点

**目标**：提升召回率和精确率，减少噪声。

#### ⑦ 混合检索（Hybrid Search）

- **技术**：同时使用**稠密向量检索**（语义）和**稀疏 BM25 检索**（关键词），通过 RRF 融合排序，取长补短。

- **实现**（LlamaIndex）：

	python

	```
	from llama_index.retrievers.bm25 import BM25Retriever
	import jieba
	
	vector_retriever = index.as_retriever(similarity_top_k=5)
	bm25_retriever = BM25Retriever.from_defaults(
	    nodes=nodes,
	    similarity_top_k=5,
	    tokenizer=lambda text: list(jieba.cut(text))  # 中文分词
	)
	hybrid_retriever = QueryFusionRetriever(
	    retrievers=[vector_retriever, bm25_retriever],
	    mode="reciprocal_rerank",
	    similarity_top_k=5
	)
	query_engine = RetrieverQueryEngine.from_args(retriever=hybrid_retriever)
	```

	

- ⭐ **工业标配**，兼顾语义理解和精确术语匹配。

#### ⑧ 多路召回（Multi-channel Retrieval）

- **技术**：使用不同嵌入模型、不同分块大小、不同数据源（如产品文档、FAQ、客服工单）同时检索，然后合并去重。

- **实现**：将多个检索器传入 `QueryFusionRetriever`，并设置 `retriever_weights` 加权融合。

	python

	```
	retriever1 = index1.as_retriever(top_k=3)  # 技术文档
	retriever2 = faq_index.as_retriever(top_k=3)  # FAQ
	fusion = QueryFusionRetriever(
	    retrievers=[retriever1, retriever2],
	    retriever_weights=[1.0, 0.8],           # 重要性权重
	    mode="relative_score"                   # 归一化后加权
	)
	```

	

#### ⑨ 多向量表示（Multi-vector / ColBERT）

- **技术**：每个文档片段用多个细粒度向量（如每个 Token 一个向量）表示，检索时计算更精细的相似度，适合长文档和细节匹配。
- **来源**：ColBERT 范式，LlamaIndex 可通过 `ColBERTRetriever` 实现（需额外安装）。

#### ⑩ 稀疏向量检索（Sparse Embedding / SPLADE）

- **技术**：结合词权重与语义向量，生成稀疏高维向量（如 SPLADE），既保留关键词重要性，又具备语义泛化能力。
- **适用**：专业术语密集的领域（医疗、法律）。

#### ⑪ 向量库索引优化

- **技术**：调整 FAISS 索引参数以平衡速度与精度。

	- **IVF**：设置 `nlist`（聚类数）和 `nprobe`（搜索簇数）。
	- **HNSW**：设置 `M`（连接数）和 `efSearch`（候选队列）。

- **示例**（FAISS IVF）：

	python

	```
	import faiss
	quantizer = faiss.IndexFlatL2(dim)
	index = faiss.IndexIVFFlat(quantizer, dim, nlist=100)
	index.train(vectors)
	index.add(vectors)
	index.nprobe = 10   # 查询时探测的聚类数，越大越准但越慢
	```

### 🔹 第三层：检索后优化（Post-retrieval）—— 5 个优化点

**目标**：清洗、精炼检索结果，为 LLM 提供高质量上下文。

#### ⑫ 上下文压缩（Context Compression）

- **技术**：对每个片段按句子与问题的语义相似度进行裁剪，只保留最相关的句子。

- **实现**：`SentenceEmbeddingOptimizer`

	python

	```
	from llama_index.core.postprocessor import SentenceEmbeddingOptimizer
	import re
	
	def chinese_sentence_split(text):
	    return [s.strip() for s in re.split(r'[。！？\n]+', text) if s.strip()]
	
	compressor = SentenceEmbeddingOptimizer(
	    embed_model=Settings.embed_model,
	    percentile_cutoff=0.5,             # 保留相似度前50%的句子
	    tokenizer_fn=chinese_sentence_split  # 必须指定中文分句器
	)
	query_engine = index.as_query_engine(node_postprocessors=[compressor])
	```

	

- ⭐ **注意**：默认分句器不支持中文，必须自定义。

#### ⑬ 去重与过滤（Deduplication & Filtering）

- **技术**：按文档 ID 或内容哈希去重，过滤相似度低于阈值的片段。
- **实践**：自定义后处理器或使用 `MetadataReplacementPostProcessor`。

#### ⑭ 重排序（Rerank）

- **技术**：用 Cross‑Encoder 模型（如 `qwen3-rerank`）对粗排候选逐个精细打分，只保留 Top‑N。

- **实现**：

	python

	```
	from llama_index.postprocessor.dashscope_rerank import DashScopeRerank
	reranker = DashScopeRerank(model="qwen3-rerank", top_n=3)
	query_engine = index.as_query_engine(
	    similarity_top_k=10,                # 先粗排召回10个
	    node_postprocessors=[reranker]      # 再精排至3个
	)
	```

	

- ⭐ **显著提升相关性**，但增加延迟（候选数通常几十到几百）。

#### ⑮ 提示工程优化（Prompt Engineering）

- **技术**：设计 System Prompt 约束角色、回答格式、禁止编造等。

- **示例**：

	python

	```
	system_prompt = (
	    "你是一个严谨的客服助手，只根据提供的文档内容回答问题。"
	    "如果文档中没有相关信息，请明确说'不知道'。"
	    "回答要简洁、有条理。"
	)
	query_engine = index.as_chat_engine(
	    system_prompt=system_prompt,
	    memory=memory
	)
	```

	

- ⭐ **关键要素**：角色、任务、规则、输出格式（可参考 CLEAR 原则）。

#### ⑯ 引用溯源（Citation）

- **技术**：在答案中标注信息来源（文档名、页码等），增强可信度。

- **实践**：在 Prompt 中要求输出来源，或从 `response.source_nodes` 提取并拼接。

	python

	```
	response = query_engine.query(question)
	for node in response.source_nodes:
	    print(node.metadata.get("file_name"), node.metadata.get("page_label"))
	```

### 🔹 第四层：进阶高级 RAG 技术 —— 4 个优化点

**目标**：赋予 RAG 自我判断、自我修正、动态策略的能力。

#### ⑰ Self-RAG（自主检索 RAG）

- **技术**：LLM 在生成过程中输出**反思标记**（Reflection Tokens）：

	- **Retrieve**：判断是否要检索。
	- **ISREL**：检查检索内容是否相关。
	- **ISSUP**：检查生成句是否有原文支撑。
	- **ISUSE**：评估答案有用性（打分）。

- **实现**：继承 `CustomQueryEngine`，在 `custom_query` 中调用多个判断函数。

	python

	```
	class SelfRAGQueryEngine(CustomQueryEngine):
	    def _need_retrieve(self, query): ...    # 调用LLM判断
	    def _is_relevant(self, query, context): ...
	    def _is_supported(self, context, answer): ...
	    def _correct(self, query, context, answer): ...
	
	    def custom_query(self, query_str):
	        if not self._need_retrieve(query_str):
	            return self.llm.complete(query_str)
	        nodes = self.retriever.retrieve(query_str)
	        if not self._is_relevant(query_str, context):
	            return "资料不相关"
	        answer = self._generate(...)
	        support = self._is_supported(context, answer)
	        if support != "FULLY":
	            answer = self._correct(...)
	        return answer
	```

	

- ⭐ **代价**：多次 LLM 调用，延迟较高，适合对准确性要求极高的场景。

#### ⑱ Corrective RAG（CRAG，纠错 RAG）

- **技术**：检索后先**逐篇评估**每个文档的相关性（用 LLM 或小模型），过滤掉无关文档。若全部无关，则**重写查询**重试，甚至触发**外部 Web 搜索**（如 Tavily）。
- **流程**：检索 → 相关性评估（yes/no） → 有 no 则改写查询 + 联网搜索 → 合并内外知识生成。
- **基础版实现**（无联网）见 `07_CRAG` 中的 `CorrectiveRAGQueryEngine`；完整版用 LlamaIndex `Workflow` 事件驱动。
- ⭐ **优势**：能有效处理检索失败的情况，减少因错误检索导致的幻觉。

#### ⑲ RAG-Fusion（融合排序）

- **技术**：多查询（Multi-Query）与多路检索（Hybrid）结合，使用 RRF 倒数排名融合得到最终排序。
- **本质**：就是 ② 和 ⑦ 的组合，通过 `QueryFusionRetriever` 同时实现查询扩展和多路融合。

#### ⑳ 自适应检索（Adaptive Retrieval）

- **技术**：根据问题难度、类型（闲聊、事实、推理）动态调整检索参数，如 `top_k`、是否检索、分块大小等。
- **实现思路**：先做意图分类，再选择不同的 `query_engine` 配置。例如简单问候直接返回，不检索；复杂问题调大 `top_k`。

## 五、RAG 常见架构模式对比（Naive → Advanced → Self-RAG → CRAG → Modular）

| 模式          | 检索前优化     | 检索方式      | 检索后优化         | 自我反思         | 联网   | 配置方式     |
| :------------ | :------------- | :------------ | :----------------- | :--------------- | :----- | :----------- |
| **Naive RAG** | 无             | 单路向量      | 无                 | 无               | 无     | 硬编码       |
| **Advanced**  | 改写/扩展/HyDE | 向量+BM25+RRF | 重排+压缩+重排序   | 无               | 无     | 硬编码       |
| **Self-RAG**  | 无             | 向量          | 无                 | 有（4种标记）    | 无     | 硬编码       |
| **CRAG**      | 无             | 向量          | 逐篇评估+过滤+重写 | 有（相关性评估） | 可选   | 硬编码       |
| **Modular**   | 可选HyDE       | 向量+BM25+RRF | 可选重排/压缩      | 依配置           | 依配置 | **配置文件** |

> **选型建议**：
>
> - 快速验证 → Naive RAG。
> - 生产环境 → Advanced RAG（混合检索 + 重排序 + 压缩）。
> - 对可靠性要求极高 → Self-RAG 或 CRAG。
> - 需要灵活切换策略 → Modular RAG。

## 六、扩展专题

### 6.1 RAG 评估（来自 `07`）

- **检索评估**：**Hit Rate**（命中率）和 **MRR**（平均倒数排名），反映检索器能否找到正确答案。

- **生成评估**：**Faithfulness**（忠实度）、**Relevancy**（相关性）、**Correctness**（正确性）。前两个无需参考答案，第三个需要人工标注。

- **代码示例**（忠实度评估）：

	python

	```
	from llama_index.core.evaluation import FaithfulnessEvaluator
	eval = FaithfulnessEvaluator()
	result = eval.evaluate_response(query="公司上班时间", response=response)
	print(result.passing)  # True/False
	```

	

### 6.2 知识图谱与 GraphRAG（来自 `08`）

- **知识图谱**：用“实体-关系-属性”结构化表示知识。

- **GraphRAG**：结合图谱和向量检索，支持多跳推理（如“张三控股哪些公司”）。

- **实现**：LlamaIndex 的 `PropertyGraphIndex` + Neo4j。

	python

	```
	from llama_index.core.indices.property_graph import SimpleLLMPathExtractor
	index = PropertyGraphIndex.from_documents(
	    documents,
	    kg_extractors=[SimpleLLMPathExtractor(llm=llm)],
	    property_graph_store=neo4j_store
	)
	query_engine = index.as_query_engine()
	```

	

### 6.3 多模态 RAG（来自 `09`）

- **支持**：文本 + 图像，可实现“以文搜图”、“以图搜图”。

- **关键**：多模态嵌入（如 Chinese-CLIP）和多模态大模型（Qwen-VL）。

- **代码**（以文搜图）：

	python

	```
	from llama_index.core.indices import MultiModalVectorStoreIndex
	index = MultiModalVectorStoreIndex.from_documents(
	    image_nodes,
	    embed_model=chinese_clip,
	    image_embed_model=chinese_clip
	)
	retriever = index.as_retriever()
	results = retriever.text_to_image_retrieve("飞机")
	```

## 八、重点难点速查表

| 难点           | 说明                                             | 应对策略                                                     |
| :------------- | :----------------------------------------------- | :----------------------------------------------------------- |
| **分块策略**   | chunk_size 和 overlap 影响检索粒度和上下文完整性 | 根据文档类型选择分割器；语义分块优于固定长度；小 chunk 提高召回，大 chunk 保上下文 |
| **检索质量**   | 召回不到正确答案                                 | 混合检索 + 多路召回 + 查询扩展；调优向量索引参数             |
| **上下文窗口** | 超长上下文会被截断或导致 LLM “迷失在中间”        | 重排序 + 压缩只保留最关键片段；使用长上下文模型（如 Qwen‑128K） |
| **幻觉**       | LLM 编造不在检索内容中的信息                     | Prompt 明确禁止编造；Self-RAG 的 ISSUP 校验；评估忠实度      |
| **延迟**       | 多步检索 + 多次 LLM 调用导致响应慢               | 索引优化（IVF/HNSW）；异步处理；缓存热门查询；减少重排序候选数 |
| **多模态**     | 图文对齐困难                                     | 使用中文 CLIP；采用端到端多模态模型（Qwen-VL）               |
