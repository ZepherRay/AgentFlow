# RAG语法总结

> 面向RAG小白的语法对比笔记。基于课件05（Naive RAG）、06（Advanced RAG）、07（Self-RAG / CRAG / Modular RAG）中的**真实代码**整理。

---

## 一、四种RAG的流程图对比

```
Naive RAG:
  查询 → 向量检索 → LLM生成 → 答案

Advanced RAG:
  查询 →[查询改写]→ 向量检索 →[重排/压缩]→ LLM生成 → 答案

Self-RAG:
  查询 →[要检索吗？]→ 向量检索 →[资料相关吗？]→ 生成 →[有证据支持吗？]→ 修正 → 答案

CRAG:
  查询 → 向量检索 →[逐篇评估相关性]→ 不相关则重写查询/上网搜 → LLM生成 → 答案
```

---

## 二、公共基础代码（所有类型都一样）

不管是哪种RAG，**起步代码**都一样：配置模型 + 加载文档 + 分块 + 建索引。

### 2.1 配置Embedding和LLM

```python
import os
from llama_index.core import Settings
from llama_index.embeddings.dashscope import DashScopeEmbedding
from llama_index.llms.dashscope import DashScope

api_key = os.getenv("DASHSCOPE_API_KEY")

# 把文本变成向量的模型（就像给文字"编码"）
Settings.embed_model = DashScopeEmbedding(
    model_name="text-embedding-v3",
    api_key=api_key,
)

# 回答问题的大模型（就像一个"读完资料后回答你"的专家）
Settings.llm = DashScope(
    model_name="qwen-plus",
    api_key=api_key,
    temperature=0.1,  # 越低回答越稳定
)
```

### 2.2 加载文档 + 分块 + 建索引

```python
from llama_index.core import SimpleDirectoryReader, VectorStoreIndex
from llama_index.core.node_parser import SentenceSplitter

# 1. 读文件
documents = SimpleDirectoryReader(input_files=["./data/kq.txt"]).load_data()

# 2. 切块（每块最多512个token，前后重叠128个避免断句）
splitter = SentenceSplitter(chunk_size=512, chunk_overlap=128)
nodes = splitter.get_nodes_from_documents(documents)

# 3. 向量化并建索引（就像建一个"图书馆索引"）
index = VectorStoreIndex(nodes)
```

> **到这一步为止，四种RAG的代码完全一样。区别从"怎么检索"和"怎么处理结果"开始。**

## 三、Naive RAG — 最简单的三步走

### 核心代码：检索 + 直接生成

```python
# 创建检索器（找最相似的5块）
retriever = index.as_retriever(similarity_top_k=5)

# 创建问答引擎（检索完直接喂给LLM）
query_engine = index.as_query_engine(
    system_prompt="根据检索内容回答问题"
)

# 问问题
response = query_engine.query("公司上下班时间是什么？")
print(response)
```

### 🔴 Naive RAG的特点
- **没有任何额外处理**，检索到什么就直接喂给LLM
- **不检查**检索结果是否有用
- **不重排**检索结果的顺序
- **不压缩**检索结果中的噪声

### 多轮对话版本

```python
from llama_index.core.memory import ChatMemoryBuffer

memory = ChatMemoryBuffer.from_defaults(token_limit=10000)

query_engine = index.as_chat_engine(
    memory=memory,  # 记住之前的对话
    system_prompt="你是一个助手，根据检索内容回答问题",
)

while True:
    question = input("请输入问题（q退出）： ")
    if question.lower() == 'q':
        break
    response = query_engine.chat(question)
    print(f"回答：{response}")
```

## 四、Advanced RAG — 加入各种"优化插件"

Advanced RAG在Naive RAG的基础上，增加了**检索前优化**和**检索后优化**。

### 4.1 检索前优化：HyDE（假设性文档检索）

**原理**：先让LLM写一个"假答案"，再用这个假答案去检索。因为假答案的语义和真正答案更接近，所以检索更准。

```python
from llama_index.core.indices.query.query_transform import HyDEQueryTransform
from llama_index.core.query_engine import TransformQueryEngine

# ① 创建HyDE转换器（让LLM先写假答案）
hyde_transform = HyDEQueryTransform(
    llm=llm,               # 用LLM生成假答案
    include_original=True,  # 同时保留原问题（双重保险）
)

# ② 包装查询引擎：先HyDE转换，再检索
hyde_query_engine = TransformQueryEngine(
    query_engine=index.as_query_engine(similarity_top_k=6),
    query_transform=hyde_transform,
)

# 使用
response = hyde_query_engine.query("向量数据库是什么")
```

**🔴 跟Naive RAG的区别**：
- Naive RAG：用户问"向量数据库是什么" → 直接拿这句话去检索
- HyDE：用户问"向量数据库是什么" → LLM先写"向量数据库是一种通过近似最近邻算法加速检索的系统" → 拿这段**假答案**去检索 → 更容易命中相关文档

### 4.2 检索前优化：Step-Back（后退一步）

**原理**：把具体问题抽象成更宽泛的背景问题，检索背景知识。

```python
from llama_index.core import PromptTemplate, QueryBundle
from llama_index.core.indices.query.query_transform.base import BaseQueryTransform

# 提示词模板
step_back_template = PromptTemplate(
    "请将用户的具体查询改写为一个更宽泛、更通用的问题。\n"
    "只输出改写后的查询文本。\n\n"
    "原始查询：{query_str}\n"
    "后退一步的查询："
)

# 自定义转换器（LlamaIndex没有内置的）
class StepBackQueryTransform(BaseQueryTransform):
    def __init__(self, llm, step_back_prompt):
        super().__init__()
        self._llm = llm
        self._step_back_prompt = step_back_prompt

    def _run(self, query_bundle: QueryBundle, metadata: dict) -> QueryBundle:
        del metadata
        prompt = self._step_back_prompt.format(query_str=query_bundle.query_str)
        broader = self._llm.complete(prompt).text.strip()
        # 宽泛问题 + 原问题，一起检索
        merged = f"{broader}\n{query_bundle.query_str}"
        return QueryBundle(query_str=merged)

# 使用
step_back_engine = TransformQueryEngine(
    query_engine=index.as_query_engine(similarity_top_k=4),
    query_transform=StepBackQueryTransform(llm=llm, step_back_prompt=step_back_template),
)

response = step_back_engine.query("大模型有哪些应用场景")
```

**🔴 跟Naive RAG的区别**：
- Naive RAG：直接搜"大模型有哪些应用场景"
- Step-Back：LLM先生成"人工智能技术在各行业的典型应用方式有哪些" → 宽泛问题 + 原问题一起搜 → 搜到更多背景信息

### 4.3 检索前优化：Multi-Query（多查询扩展）

**原理**：让LLM围绕原问题生成N个变体，多路检索后融合。

```python
from llama_index.core.retrievers import QueryFusionRetriever
from llama_index.core.query_engine import RetrieverQueryEngine

base_retriever = index.as_retriever(similarity_top_k=4)

# 多查询融合检索器
multi_query_retriever = QueryFusionRetriever(
    retrievers=[base_retriever],   # 基础检索器
    llm=llm,                       # 用于生成变体查询
    similarity_top_k=4,            # 融合后返回4个结果
    num_queries=4,                 # 1个原问题 + 3个变体 = 4路检索
    mode="reciprocal_rerank",      # RRF融合算法
    use_async=False,
    verbose=True,
)

multi_query_engine = RetrieverQueryEngine.from_args(
    retriever=multi_query_retriever,
    llm=llm,
)

response = multi_query_engine.query("大模型有哪些应用场景")
```

**🔴 跟Naive RAG的区别**：
- Naive RAG：1个问题 → 检索1次
- Multi-Query：1个问题 → LLM生成3个变体 → 4路并行检索 → RRF融合排序

### 4.4 检索前优化：SubQuestion（子问题分解）

**原理**：复杂问题拆成多个子问题，每个子问题去不同知识库检索。

```python
from llama_index.core.query_engine import SubQuestionQueryEngine
from llama_index.core.tools import QueryEngineTool, ToolMetadata

# 把不同知识库包装成"工具"
tools = [
    QueryEngineTool(
        query_engine=policy_index.as_query_engine(similarity_top_k=3),
        metadata=ToolMetadata(
            name="ai_policy",
            description="中国政府关于AI的政策信息",
        ),
    ),
    QueryEngineTool(
        query_engine=enterprise_index.as_query_engine(similarity_top_k=3),
        metadata=ToolMetadata(
            name="enterprise_impact",
            description="AI政策对企业的影响",
        ),
    ),
]

# 子问题分解引擎
sub_question_engine = SubQuestionQueryEngine.from_defaults(
    query_engine_tools=tools,
    llm=llm,
    verbose=True,
)

# 复杂问题会被自动拆解
response = sub_question_engine.query(
    "中国政府在AI上有哪些政策？这些政策对企业和研究机构分别有什么影响？"
)
# 自动拆成：
# 子问题1：中国政府在AI上有哪些政策？
# 子问题2：这些政策对企业有什么影响？
```

### 4.5 检索优化：混合检索（BM25 + 向量 + RRF融合）

**原理**：向量检索抓语义，BM25抓关键词，两路融合更全面。

```python
import jieba
from llama_index.retrievers.bm25 import BM25Retriever
from llama_index.core.retrievers import QueryFusionRetriever

# 路1：向量检索（语义匹配）
vector_retriever = index.as_retriever(similarity_top_k=5)

# 路2：BM25检索（关键词匹配，用jieba分中文）
bm25_retriever = BM25Retriever.from_defaults(
    nodes=nodes,
    similarity_top_k=5,
    tokenizer=lambda text: list(jieba.cut(text)),  # jieba中文分词
)

# RRF融合两路结果
hybrid_retriever = QueryFusionRetriever(
    retrievers=[vector_retriever, bm25_retriever],
    similarity_top_k=5,
    num_queries=1,              # 不扩展查询，只做融合
    mode="reciprocal_rerank",   # RRF算法
    verbose=True,
)

# 组装引擎
query_engine = RetrieverQueryEngine.from_args(retriever=hybrid_retriever)
```

**🔴 跟Naive RAG的区别**：
- Naive RAG：只有向量检索1路
- 混合检索：向量 + BM25 2路，RRF融合排序

### 4.6 检索后优化：重排序（Reranking）

**原理**：粗排召回多一些候选，然后用更精确的模型重新打分排序。

```python
from llama_index.postprocessor.dashscope_rerank import DashScopeRerank

# 重排器（Cross-Encoder精排）
reranker = DashScopeRerank(
    model="qwen3-rerank",  # 重排模型
    top_n=3,               # 精排后只留3个
    api_key=api_key,
)

# 方式A：手动调用
candidates = retriever.retrieve(query)  # 先粗排召回6个
reranked = reranker.postprocess_nodes(candidates, query_str=query)  # 再精排到3个

# 方式B（推荐）：塞进查询引擎自动执行
query_engine = index.as_query_engine(
    similarity_top_k=6,                  # 粗排多召回一些
    node_postprocessors=[reranker],      # 自动精排
)
```

### 4.7 检索后优化：上下文压缩（Compression）

**原理**：召回的片段里可能只有1-2句有用，压缩掉无关句子。

```python
from llama_index.core.postprocessor import SentenceEmbeddingOptimizer
import re

def chinese_sentence_split(text):
    """中文按句号拆分"""
    return [s.strip() for s in re.split(r'[。！？\n]+', text) if s.strip()]

compressor = SentenceEmbeddingOptimizer(
    embed_model=Settings.embed_model,
    percentile_cutoff=0.5,           # 保留最相关的50%句子
    tokenizer_fn=chinese_sentence_split,  # 中文分句（重要！默认不支持中文）
    context_before=0,
    context_after=0,
)

query_engine = index.as_query_engine(
    similarity_top_k=3,
    node_postprocessors=[compressor],
)
```

### 4.8 检索后优化三件套组合

```python
from llama_index.core.postprocessor import LongContextReorder

reranker = DashScopeRerank(model="qwen3-rerank", top_n=5, api_key=api_key)
compressor = SentenceEmbeddingOptimizer(
    embed_model=Settings.embed_model,
    percentile_cutoff=0.5,
)
reorder = LongContextReorder()  # 解决LLM"迷失在中间"问题

# 三件套按顺序执行：重排 → 压缩 → 重排序
query_engine = index.as_query_engine(
    similarity_top_k=10,                                    # 先多召回
    node_postprocessors=[reranker, compressor, reorder],    # 再三连优化
)
```

## 五、Self-RAG — 带自我反思的RAG

### 核心思想

让LLM在每个环节**自我检查**：
1. **Retrieve**（要不要检索？）：简单问题可能不需要检索
2. **ISREL**（资料相关吗？）：过滤不相关的检索结果
3. **ISSUP**（回答有证据支持吗？）：检测幻觉
4. **ISUSE**（回答有用吗？）：评估最终质量

### 完整代码

```python
from llama_index.core.query_engine import CustomQueryEngine
from llama_index.core.base.base_retriever import BaseRetriever
from llama_index.core.llms import LLM

class SelfRAGQueryEngine(CustomQueryEngine):
    retriever: BaseRetriever  # 检索器
    llm: LLM                  # 大模型
    verbose: bool = True

    def _judge(self, prompt: str) -> str:
        """让LLM做一个判断（YES/NO等）"""
        return self.llm.complete(prompt).text.strip()

    # ---- 反思1：要不要检索？----
    def _need_retrieve(self, query: str) -> bool:
        ans = self._judge(
            "判断下面的问题是否需要检索外部知识。\n"
            "只输出：YES 或 NO。\n\n"
            f"问题：{query}"
        )
        return "YES" in ans.upper()

    # ---- 反思2：资料相关吗？----
    def _is_relevant(self, query: str, context: str) -> bool:
        ans = self._judge(
            "判断检索到的资料是否与问题相关。\n"
            "只输出：RELEVANT 或 IRRELEVANT。\n\n"
            f"问题：{query}\n资料：{context}"
        )
        return "IRRELEVANT" not in ans.upper()

    # ---- 反思3：回答有证据支持吗？----
    def _is_supported(self, context: str, answer: str) -> str:
        return self._judge(
            "判断回答在多大程度上被资料支撑。\n"
            "只输出：FULLY / PARTIALLY / NO。\n\n"
            f"资料：{context}\n回答：{answer}"
        ).upper()

    # ---- 反思4：回答有用吗？----
    def _usefulness(self, query: str, answer: str) -> str:
        return self._judge(
            "给回答的有用程度打分（1~5分）。\n只输出数字。\n\n"
            f"问题：{query}\n回答：{answer}"
        )

    # ---- 自我修正 ----
    def _correct(self, query: str, context: str, answer: str) -> str:
        return self._judge(
            "基于资料重写回答，确保无幻觉、完整回答问题。\n\n"
            f"资料：{context}\n问题：{query}\n原回答：{answer}\n\n修正后："
        )

    # ==================== 主流程 ====================
    def custom_query(self, query_str: str) -> str:
        # Step1: 判断要不要检索
        if not self._need_retrieve(query_str):
            print("[Retrieve=NO] 无需检索，直接回答")
            return self.llm.complete(query_str).text.strip()

        # 检索
        nodes = self.retriever.retrieve(query_str)
        context = "\n".join(n.get_content() for n in nodes)

        # Step2: 资料相关吗？
        if not self._is_relevant(query_str, context):
            print("[ISREL=IRRELEVANT] 资料不相关")
            return "检索到的资料与问题不相关。"

        # 生成回答
        answer = self._judge(
            f"请仅依据以下资料回答问题。\n资料：{context}\n问题：{query_str}\n回答："
        )

        # Step3: 有证据支持吗？不足则修正
        support = self._is_supported(context, answer)
        if support != "FULLY":
            answer = self._correct(query_str, context, answer)
            print("→ 支持度不足，已自我修正")

        # Step4: 评估有用性（仅记录）
        print(f"[ISUSE={self._usefulness(query_str, answer)}/5]")

        return answer

# 使用
self_rag = SelfRAGQueryEngine(retriever=retriever, llm=Settings.llm)
response = self_rag.query("公司上下班时间是什么？")
```

### 🔴 跟Naive RAG的区别

| 步骤 | Naive RAG | Self-RAG |
|------|-----------|----------|
| 检索前 | 直接检索 | LLM判断**要不要检索** |
| 检索后 | 直接喂给LLM | LLM检查**资料相关吗** |
| 生成后 | 直接返回 | LLM检查**有证据支持吗**，不足则**自我修正** |
| 质量评估 | 无 | LLM打分**有用吗**（1-5分） |

### 🔴 跟Advanced RAG的区别
- Advanced RAG用**算法**做重排序和压缩
- Self-RAG用**LLM判断**做质量控制，更智能但更慢（每次判断都调一次LLM）

## 六、CRAG（Corrective RAG）— 带纠正机制的RAG

### 核心思想

检索后**逐篇评估**每篇文档的相关性，过滤掉无关文档。如果全部不相关，**重写查询重新检索**。完整版还可以**上网搜**补充知识。

### 6.1 基础版（只在本地知识库修正）

```python
from llama_index.core.prompts import PromptTemplate
from llama_index.core.query_engine import CustomQueryEngine

# 三个提示词
RELEVANCE_PROMPT = PromptTemplate(
    "判断文档片段是否与用户问题相关。\n只输出：RELEVANT 或 IRRELEVANT。\n\n"
    "用户问题：{query}\n文档片段：{document}\n输出："
)
REWRITE_PROMPT = PromptTemplate(
    "原始问题检索不到相关信息，请改写得更清晰具体。\n只输出改写后的问题。\n\n"
    "原始问题：{query}\n改写后："
)
ANSWER_PROMPT = PromptTemplate(
    "请仅依据以下相关文档回答问题，不要编造。\n\n"
    "相关文档：\n{context}\n\n用户问题：{query}\n回答："
)

class CorrectiveRAGQueryEngine(CustomQueryEngine):
    retriever: BaseRetriever
    llm: LLM
    verbose: bool = True

    def _is_relevant(self, query, doc):
        resp = self.llm.complete(
            RELEVANCE_PROMPT.format(query=query, document=doc)
        ).text.strip().upper()
        return "IRRELEVANT" not in resp

    def _filter_relevant(self, query, nodes):
        """逐篇评估，过滤无关文档"""
        kept = []
        for i, n in enumerate(nodes, 1):
            text = n.get_content()
            ok = self._is_relevant(query, text)
            print(f"  文档{i}：{'✅相关' if ok else '❌无关'}")
            if ok:
                kept.append(text)
        return kept

    def custom_query(self, query_str):
        # 步骤1：检索（多召回一些）
        nodes = self.retriever.retrieve(query_str)
        print(f"[1] 初始检索到 {len(nodes)} 篇文档")

        # 步骤2：逐篇过滤（CRAG核心！）
        print("[2] 文档相关性过滤中...")
        relevant = self._filter_relevant(query_str, nodes)

        # 步骤3：全部不相关 → 重写查询重检索
        if not relevant:
            print("[3] 信息不足，重写查询并重检索...")
            new_query = self.llm.complete(
                REWRITE_PROMPT.format(query=query_str)
            ).text.strip()
            print(f"   改写后：{new_query}")
            relevant = self._filter_relevant(
                query_str, self.retriever.retrieve(new_query)
            )

        if not relevant:
            return "知识库中没有足够信息回答该问题。"

        # 步骤4：用相关文档生成回答
        context = "\n---\n".join(relevant)
        return self.llm.complete(
            ANSWER_PROMPT.format(query=query_str, context=context)
        ).text

# 使用
crag = CorrectiveRAGQueryEngine(
    retriever=index.as_retriever(similarity_top_k=5),
    llm=Settings.llm,
)
```

### 6.2 完整版（可联网搜索补充）

完整版在"全部不相关"时，不再只搜本地库，而是**用Tavily去网上搜**。

```python
from llama_index.core.workflow import Workflow, step, Context, Event, StartEvent, StopEvent
from llama_index.tools.tavily_research.base import TavilyToolSpec

class CorrectiveRAGWorkflow(Workflow):
    @step
    async def retrieve(self, ctx, ev):
        """检索"""
        nodes = index.as_retriever(similarity_top_k=5).retrieve(ev.query_str)
        return RetrieveEvent(retrieved_nodes=nodes)

    @step
    async def eval_relevance(self, ctx, ev):
        """逐篇评估（CRAG核心）"""
        results = []
        for node in ev.retrieved_nodes:
            resp = await Settings.llm.acomplete(
                RELEVANCY_PROMPT.format(
                    context_str=node.get_content(),
                    query_str=await ctx.store.get("query_str")
                )
            )
            results.append(resp.text.lower().strip())
        return RelevanceEvalEvent(relevant_results=results)

    @step
    async def transform_query(self, ctx, ev):
        """有不相关文档时：重写查询 + Tavily联网搜索"""
        if "no" in ev.relevant_results:
            new_query = await Settings.llm.acomplete(
                TRANSFORM_QUERY_PROMPT.format(query_str=await ctx.store.get("query_str"))
            )
            tavily = await ctx.store.get("tavily_tool")
            search_results = tavily.search(new_query.text.strip(), max_results=5)
            search_text = "\n".join(r.text for r in search_results)
        else:
            search_text = ""
        # ... 合并内部+外部文本，生成最终答案
```

### 🔴 CRAG跟Self-RAG的区别

| 维度 | Self-RAG | CRAG |
|------|----------|------|
| **评估对象** | 先检查"要不要检索"，再检查"资料相关吗" | 直接检索，然后**逐篇评估**每篇文档 |
| **过滤方式** | 把所有检索结果拼在一起判断整体相关性 | **逐篇打标**RELEVANT/IRRELEVANT，过滤掉无关的 |
| **纠正方式** | ISSUP不足时让LLM修正回答 | 全部不相关时**重写查询重检索**，完整版还能**联网搜** |
| **联网能力** | 无 | 完整版支持Tavily Web搜索 |
| **代码结构** | 继承`CustomQueryEngine`，线性流程 | 基础版继承`CustomQueryEngine`；完整版用`Workflow`事件驱动 |

## 七、Modular RAG — 配置驱动的模块化RAG

### 核心思想

把RAG拆成独立模块（检索器、重排器、压缩器等），通过**配置文件**控制哪些模块开启、哪些关闭。

### 7.1 模块注册 + 注册表

```python
# 注册表：所有可用模块都登记在这里
REGISTRY = {}

def register(category: str, desc: str):
    def decorator(cls):
        key = f"{category}.{cls.__name__}"
        REGISTRY[key] = {"class": cls, "desc": desc}
        return cls
    return decorator

# 注册检索器
@register("retriever", "向量检索器")
class VectorRetriever:
    def retrieve(self, query, top_k=5):
        return self.index.similarity_search(query, k=top_k)

# 注册重排器
@register("reranker", "交叉编码重排器")
class CrossEncoderReranker:
    def rerank(self, query, nodes, top_k=5):
        scores = self.model.predict([(query, n.text) for n in nodes])
        ranked = sorted(zip(nodes, scores), key=lambda x: x[1], reverse=True)
        return [n[0] for n in ranked[:top_k]]
```

### 7.2 配置驱动的主编排类

```python
from dataclasses import dataclass

@dataclass
class PipelineConfig:
    """管道配置（就像RAG的"遥控器"）"""
    top_k: int = 5                    # 检索多少个结果
    fusion_mode: str = "reciprocal_rerank"  # 融合算法
    num_queries: int = 1              # 是否多查询扩展
    enable_rerank: bool = False       # 是否启用重排
    enable_compression: bool = False  # 是否启用压缩
    enable_hyde: bool = False         # 是否启用HyDE

class ModularRAG:
    def __init__(self, config: PipelineConfig):
        self.config = config
        self.query_engine = None

    def index_documents(self, raw_docs):
        """根据配置组装RAG管道"""
        # 1. 建索引
        index, nodes = build_index(raw_docs)

        # 2. 多路检索
        vector_retriever = index.as_retriever(top_k=self.config.top_k)
        bm25_retriever = BM25Retriever(nodes=nodes, top_k=self.config.top_k)

        # 3. 融合
        retriever = QueryFusionRetriever(
            retrievers=[vector_retriever, bm25_retriever],
            num_queries=self.config.num_queries,
            mode=self.config.fusion_mode,
        )

        # 4. 后处理（根据配置开关）
        postprocessors = []
        if self.config.enable_rerank:
            postprocessors.append(DashScopeRerank(top_n=3))
        if self.config.enable_compression:
            postprocessors.append(SentenceEmbeddingOptimizer(percentile_cutoff=0.5))

        # 5. 组装
        self.query_engine = RetrieverQueryEngine(
            retriever=retriever,
            node_postprocessors=postprocessors,
        )

        # 6. 可选HyDE
        if self.config.enable_hyde:
            self.query_engine = TransformQueryEngine(
                query_engine=self.query_engine,
                query_transform=HyDEQueryTransform(include_original=True),
            )

    def query(self, question):
        return self.query_engine.query(question)

# 使用：改配置就行，不用改代码
rag = ModularRAG(PipelineConfig(
    top_k=5,
    enable_rerank=True,
    enable_compression=True,
    enable_hyde=False,
))
rag.index_documents(documents)
response = rag.query("什么是RAG？")
```

### 🔴 跟前面三种RAG的区别

| 维度 | Naive/Advanced/Self/CRAG | Modular RAG |
|------|--------------------------|-------------|
| **代码组织** | 散落在各处，手动拼接 | 注册表 + 配置类，模块化 |
| **切换策略** | 改代码 | 改配置字典 |
| **扩展性** | 加新策略要到处改 | `@register` 注册即用 |
| **预设模式** | 无 | basic / hybrid / advanced / full_optimization |

## 八、一张表总结所有差异

| RAG类型 | 检索前优化 | 检索方式 | 检索后优化 | 自我反思 | 联网 | 配置方式 |
|---------|-----------|---------|-----------|---------|------|---------|
